Create & Destroy

Full steps: S3 + Terraform state, Atlantis (Docker), AWS, app image — environments/dev

Remote state lives in S3. The Terraform state file object is set by backend.tf (bucket + key). For remote state locking, either add a dynamodb_table to the backend, or use Terraform 1.10+ and uncomment use_lockfile = true in the root terragrunt.hcl (S3-native locks).

Create — all steps

1) AWS CLI credentials

Install AWS CLI; configure a profile or env vars Terraform and Atlantis can use.

aws configure # or export AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY / AWS_REGION

2) S3 bucket for Terraform state (before first terraform init)

Bucket name must match environments/dev/backend.tf. Creating the bucket does not create the state file; terraform init + apply upload dev/terraform.tfstate to S3.

export AWS_REGION=us-east-1 export TF_STATE_BUCKET=react-app-tfstate-laith aws s3 mb "s3://${TF_STATE_BUCKET}" --region "${AWS_REGION}" aws s3api put-bucket-versioning \ --bucket "${TF_STATE_BUCKET}" \ --versioning-configuration Status=Enabled aws s3api put-bucket-encryption \ --bucket "${TF_STATE_BUCKET}" \ --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}' aws s3api put-public-access-block \ --bucket "${TF_STATE_BUCKET}" \ --public-access-block-configuration \ BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

Do not delete this bucket while Terraform still manages infrastructure; the state file is the source of truth.

3) (Optional) DynamoDB table for locking

Only if you switch backend.tf to use dynamodb_table. Current config does not require it.

aws dynamodb create-table \ --table-name terraform-locks \ --attribute-definitions AttributeName=LockID,AttributeType=S \ --key-schema AttributeName=LockID,KeyType=HASH \ --billing-mode PAY_PER_REQUEST \ --region us-east-1

4) Atlantis (Docker) + GitHub webhook

Atlantis runs on your machine (or a server). GitHub must reach it; locally use ngrok on port 4141.

ngrok http 4141 # Copy https://YOUR-SUBDOMAIN.ngrok-free.app
docker run -d --name atlantis --restart unless-stopped -p 4141:4141 \ -e ATLANTIS_GH_USER="YOUR_GITHUB_USERNAME" \ -e ATLANTIS_GH_TOKEN="ghp_YOUR_PAT_WITH_REPO_SCOPE" \ -e ATLANTIS_REPO_ALLOWLIST="github.com/YOUR_USER_OR_ORG/react-app-infra" \ -e ATLANTIS_ATLANTIS_URL="https://YOUR-SUBDOMAIN.ngrok-free.app" \ -e AWS_ACCESS_KEY_ID="YOUR_AWS_ACCESS_KEY" \ -e AWS_SECRET_ACCESS_KEY="YOUR_AWS_SECRET_KEY" \ -e AWS_REGION="us-east-1" \ ghcr.io/runatlantis/atlantis:latest server

GitHub webhook: Payload URL https://YOUR-SUBDOMAIN.ngrok-free.app/events — events: Pull requests, Issue comments, Pushes as needed. Match webhook secret to Atlantis if you set one.

docker logs -f atlantis

5) Terraform: init, plan, apply (environments/dev)

State reads/writes S3 after init.

cd environments/dev terraform init terraform plan terraform apply

With Atlantis: open a PR → plan → comment atlantis apply -p dev when ready.

6) Container image to ECR (ARM for Graviton EC2)

./scripts/docker-push-ecr.sh

If EC2 booted before the image existed, bump user_data or run ./scripts/replace-ec2-instance.sh, then apply again.

7) Open the app

terraform output public_ip # browser: http://PUBLIC_IP

Destroy — order matters

Teardown

  1. Run terraform destroy in environments/dev while state still exists in S3.
  2. Confirm resources gone in AWS Console.
  3. Then empty the state bucket (state file + lock objects), then delete the bucket.
  4. Delete DynamoDB lock table only if you used that backend mode.
  5. docker stop atlantis; stop ngrok.
cd environments/dev terraform destroy
aws s3 rb s3://react-app-tfstate-laith --force

--force empties the bucket. Adjust name. DynamoDB (only if used): aws dynamodb delete-table --table-name terraform-locks --region us-east-1

Quick ref

Terraform does not delete your git repo, local Docker images, or ~/.aws. GitHub webhooks are manual.

State Keep S3 until after destroy; then empty + delete bucket.
Atlantis Stop container when done.
